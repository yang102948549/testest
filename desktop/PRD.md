# 시험감독 배정 프로그램 PRD

기준일: 2026-10-01 · 제작자: **양양**

현재 코드: 앱 1.2.0 / 엔진 2.0.0-highs / 문서 스키마 version 1.
업무 절차는 [WORKFLOW](WORKFLOW.md), 배포 계획은 [DISTRIBUTION](DISTRIBUTION.md), 검증 기록은 [VERIFICATION](VERIFICATION.md)을 참고한다.

## 1. 목적과 대상

학교 시험 담당자가 교사 조건과 시험 일정을 입력하면 금지 조건을 지키면서 지정배치·자리 선호를 우선하고 일반교사의 감독 점수를 균등하게 배정하는 Windows 데스크톱 프로그램이다. 담당자는 결과와 미충족 사유를 확인하고 수동 조정한 뒤 배정표를 내보낸다.

핵심 업무는 오프라인으로 실행한다. 외부 명단·시간표 가져오기와 향후 업데이트 확인에는 인터넷이 필요하다. 교사·고사 데이터의 클라우드 동기화는 범위에 포함하지 않는다.

| 수동 조정 | 구현 | 배정·해제·교환, 임시 변경, 명시적 반영 |

## 3. 시험·교사 입력

- 고사 이름, 시험 날짜·교시, 학년별 과목·적용 고사실을 설정한다. 교실·복도·특별실을 등록하고 이름 대신 ID로 연결한다.
- 일반 감독과 정/부 감독 모드를 지원한다. 정/부 모드는 단독 감독실을 교시별로 지정한다.
- 해당 교시의 모든 등록 과목이 자습이면 일반 모드의 복도 자리, 정/부 모드의 부감독 자리를 만들지 않는다.
- 교사 이름, 복수 담당 과목, 담임학급, 감독불가학급, 역할, 자리 선호, 가능·지정 교시와 사유를 관리한다.
- 일반교사와 제외교사를 제외한 역할은 지정교사로 취급하며 체크한 활성 시험 교시에만 배정한다. 지정 교시가 없으면 배정하지 않는다.
- 일반교사의 `availability = null`은 전체 가능, 빈 배열은 가능 교시 없음이다. 기존 제외 기록은 가능 목록보다 우선한다.
- 가져오기에서 열 연결·역할·학급 연결·동명이인을 확인한다. 원본에 없는 담임이나 역할은 사용자가 보완해야 하며 엔진이 추론하지 않는다.
- 솔버의 최적성은 입력된 모델에 대한 판정이다. 실제 업무 조건의 누락까지 검증했다는 의미가 아니다.

## 4. 필수 제약

| 조건 | 처리 |
|---|---|
| 감독 제외 역할 | 배정 후보에서 제외 |
| 불가능·제외 교시 또는 지정교사의 미지정 교시 | 후보에서 제외 |
| 담임학급·감독불가학급 | 해당 고사실 후보에서 제외 |
| 담당 과목 시험 | 해당 교시 전체 학년 시험과목 중 일치 과목이 있으면 제외 |
| 복도 전담·부감독 전담 | 일반 시험의 교실·정감독 금지. 자습은 기존 예외 적용 |
| 동시간 중복 | 교사당 동일 날짜·교시에 최대 한 자리 |
| 자리 중복 | 한 자리에 최대 한 교사 |

시간 제한, 지정배치 요청, 점수 개선 때문에 제약을 완화하지 않는다. 자동·수동 배정에 공통으로 적용한다.

## 5. HiGHS 엔진

우선순위를 큰 가중치 하나로 합치지 않고 다음 순서대로 최적화한다. 앞 단계에서 최적성이 확인된 목적값을 유지하면서 다음 단계에서 교사를 재배치할 수 있다.

| 순서 | 최소화 대상 | 의미 |
|---|---|---|
| 1 | 지정배치 미충족 | 지정교사를 체크한 교시에 최대한 배정 |
| 2 | 빈자리 수 | 지정배치 수준을 유지하며 충원 |
| 3 | 지정교사 자리 선호 위반 | 교실 우선·복도 우선 등의 선호 충족 |
| 4 | 일반교사 최고·최저 점수 차이 | 지정교사·제외교사를 제외한 점수 균등화 |
| 5 | 일반교사 평균과의 절대 편차 합 | 같은 점수 범위 내에서 추가 균등화 |

**현행 구현에서는 빈자리 충원이 자리 선호보다 우선한다.** 자리 선호는 점수 균등화보다 우선한다. 일반교사의 역할 선호·일별 쏠림·연속 감독·같은 고사실 반복은 최적화 목적이 아니다.

일반 모드 점수는 `교실 횟수 × 교실 가중치 + 복도 횟수 × 복도 가중치`이다. 기본 2점·1점은 변경 가능하며 0 이상 유한 소수와 100을 넘는 값도 허용한다. 특별실의 일반 감독은 교실 점수로 계산한다. 내부 정규화 후 원래 단위로 결과를 표시하며 양수 가중치 비율이 1억 배를 초과하면 입력 조정을 요청한다.

**정/부 모드는 현재 건당 1점이다.** 정·부 가중치까지 사용자 설정으로 확장하려면 별도 요구사항과 구현 변경이 필요하다. 전체·일일 횟수 기준은 참고 경고이며 강제 상한이나 최적화 목적이 아니다.

### 결과와 시간 제한

- 교시별 매칭으로 초기 배치안을 확보하고 Worker에서 HiGHS를 실행한다. WASM을 앱에 포함하므로 Python이나 인터넷이 필요하지 않다.
- 전체 계산 예산은 약 10초이며 초기화·모델 생성 등으로 실제 반환 시간은 늘어날 수 있다. 모든 사례의 최적해나 10초 이내 반환을 보장하지 않는다.
- 전체 단계가 허용오차 내에서 증명된 경우에만 ‘최적해 확인’을 표시한다. 시간 제한 시 확보한 유효 배치와 완료 단계·최적성 미확인을 표시한다.
- 최적해여도 미배정·지정 미충족이 남을 수 있다. 동일 seed라도 시간 제한 결과가 항상 같지는 않다.
- 결과를 별도 검증기로 검사한다. 입력 변경·수동 조정 후 기존 최적성 표시를 유지하지 않는다.
- 취소 시 Worker를 종료하고 이전 결과를 보존한다.

## 6. 저장·보안·사용성

- 고사 데이터는 사용자 데이터 폴더에 저장하고 설치 폴더와 분리한다.
- 자동 저장, Ctrl+S, 임시 파일 후 교체, 직전 정상본 백업을 지원한다. 저장 실패와 복구 여부를 알린다.
- 수동 배정 변경은 별도 임시 상태로 유지하고 사용자가 반영해야 문서에 적용한다.
- JSON 가져오기는 새 고사 ID를 부여하여 기존 고사를 덮어쓰지 않는다.
- renderer의 Node 권한을 차단하고 sandbox·context isolation과 제한된 IPC를 사용한다.
- 발급 개인키와 향후 코드서명 자격정보는 앱·배포 저장소에 포함하지 않는다.
- 향후 업데이트는 미저장 작업을 보존하고 데이터 형식 변경 전에 백업·마이그레이션을 검증해야 한다.

## 7. 배포 목표와 제외 범위

공통 Windows EXE, 최초 실행 라이선스 파일 인증, `electron-updater`와 GitHub Releases를 이용한 사용자 승인형 업데이트를 목표로 한다. 설치 중 CD키 입력과 패치마다 구매자에게 EXE를 개별 전달하는 운영은 폐기한다. [배포 인수 기준](DISTRIBUTION.md)을 통과한 뒤 출시한다.

오프라인 영구 라이선스를 기본으로 한다. 로그인, 결제 연동, 기기 수 제한, 원격 인증 취소, 강제 업데이트, 자동 고사 데이터 업로드는 범위에서 제외한다. 파일 복제를 막는 온라인 DRM으로 설명하지 않는다.

## 8. 검증 기준

- 작은 사례 전수 탐색과 사전식 최적화 결과 비교, 금지 제약, 지정배치 충돌, 소수·0·큰 가중치, 시간 제한을 회귀 검증한다.
- 저장·복구·가져오기·수동 교환·취소·재시작과 대표 대규모 입력을 검증한다.
- 기존 기록상 8개 파일 65개 테스트와 Electron 통합 검증이 통과했다. 모든 학교 데이터에서의 성능·최적성 보장은 아니다.
- 새 인증·업데이트 구현 후 별도 Windows PC에서 신규 설치, 이전 버전 업그레이드, 실패 복구, 인증·데이터 유지 검증을 추가한다.
