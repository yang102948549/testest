# 1차 빌드 검증 기록

검증 환경: Windows x64, Node.js 22.16.0, Electron 40.10.6.

## 자동 테스트

- 규칙·알고리즘 16건, 저장 2건: 총 18건 통과.
- 같은 입력·seed의 배정 재현, JSON 필드 순서 변화에 대한 입력 서명 안정성을 확인했습니다.
- 작은 2교사·2고사실 사례의 16개 금지 조합을 전수 탐색 결과와 비교했습니다.
- 일반·정/부 모드, 단독 감독실, 자습, 동명이인, 담당 과목, 담임·이동학급, 완전 제외, 가능·제외 시간, 필수배치 충돌, 미배정 사유, 상한 초과, 수동 중복·금지 변경 거부를 확인했습니다.
- JSON 왕복, 새 저장소 인스턴스에서 복원, 원본 손상 시 백업 복구, 잘못된 문서 저장 거부, 동시 저장 순서를 확인했습니다.

## 실제 Windows 패키지

`release/win-unpacked/시험감독.exe`를 Playwright Electron으로 실행해 확인했습니다. 테스트 프로필은 `test-artifacts/`에 별도로 생성했습니다.

- 빈 고사에서 날짜·고사실·과목·교사를 입력한 뒤 자동 배정.
- 예시 고사에 교사를 추가하고 제외 사유 입력.
- 자동 배정 후 두 자리 교환, 수동 해제·직접 배정, 실행 취소.
- JSON 내보내기·가져오기, 손상 파일 거부, 기존 고사 덮어쓰기 방지.
- 실제 창 닫기와 앱 재실행 후 고사·배정 복원.
- 모드 변경 후 오래된 결과 감지, 재검증, 정/부 감독 재배정.
- 대규모 계산 도중 화면 이동 및 취소.
- 100명·40실·5일·4교시 사례: 800자리 모두 배정, 금지 조건 위반 0건. 패키지에서 계산·렌더링·저장까지 약 8초였습니다. 실행 환경에 따라 달라집니다.
- renderer 오류 0건, 원격 HTTP 요청 0건.

테스트의 파일 대화상자는 격리된 Electron 테스트 프로세스 안에서 테스트 경로를 반환하도록 대체했습니다. 운영 앱의 대화상자와 저장 코드는 그대로 사용합니다. 설치 파일을 사용자의 Windows에 실제 설치해 레지스트리·바로가기를 변경하는 테스트는 하지 않았습니다.

## 산출물과 한계

- Windows x64 NSIS 설치 파일 및 독립 실행 폴더 생성 완료.
- 앱 이름·버전·아이콘 리소스 포함. 코드서명 인증서는 적용하지 않았습니다.
- 합성 예시 데이터로 검증했으며, 실제 학교 고사 데이터로 검증한 것은 아닙니다.
- 알고리즘은 금지 조건을 검증하는 제한 탐색입니다. 전역 최적해 또는 해의 부재를 증명하지 않습니다.
- 캡처 이미지와 원시 통합 테스트 보고서는 `test-artifacts/`에 생성됩니다.
